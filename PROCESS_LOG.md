# Process Log

## 1. AI tools used

- Cursor, with Grok 4.7, on 14–18 November 2026. This was the coding assistant. It drafted modules, tests, the threat model, the performance notes, and the deploy wiring.
- Ollama `gemma4:e2b` on this PC, used as the local model while routing and the demo were tested. It was not used to write the Python.

## 2. Development narrative

I built Lumen from the plan outward: a Hermes agent on a Cloud Run instance, memory on a Cloud Storage bucket, and Gemma on my laptop through Tailscale. On 14 November I asked Cursor to draft the hybrid router, the email approval gate, the calendar and deadline helpers, and the four skill scripts from `plan.md`. The unit tests for those pieces passed the same day, with OpenAI and Ollama mocked.

Deployment was where the drafts stopped matching the running system. Hermes cron wiped `EMAIL_IMAP_HOST` from job subprocesses, so the alert scan failed until a runtime env file was written at boot. Slack stayed silent until I invited the bot into the channel. Discord ignored role mentions and, for a normal channel message, answered inside a thread. The first cross-platform memory test failed for a different reason. "Remember that my project is Bluebird" was under 80 characters, so the router called Gemma with only that sentence and never the shared memory file. I got unstuck by reading the router classifier, the gateway log, and Hermes's memory tool, then by sending "Explain and save in memory..." so the turn stayed on the cloud model.

The 48-hour window stayed up without a restart. Morning briefings and evening recaps fired. Health checks timed out when the laptop slept, which the assignment treats as local inference being unavailable, not a crash. The recording added its own traps: quitting the tray icon left `ollama.exe` running, and `gcloud ssh` failed until the Cloud SDK was reached through a path with no spaces. Specific prompts that produced code I kept were "draft the send gate so cron cannot send and only an exact APPROVE from the owner to an allowlisted recipient works" and "add a web chat that blocks send approval when the session is the grader API."

## 4. Verification narrative

I did not treat a successful draft as a passing feature. `python -m unittest` covers the calendar fixture, deadline labels, the send gate, untrusted search snippets, every router reason, the web chat, and the web-approval block. OpenAI and Ollama were mocked in those tests. Separately, I ran live router calls and recorded the model, latency, and token counts in `reports/PERFORMANCE.md`. The three injection checks called the gate and the snippet wrapper directly. They were not a live chat, and the write-up says so.

For the running instance I traced behavior in the bucket and in Cloud Logging instead of trusting the model's reply. I matched briefing and recap files to the job clock, counted journal rows inside the 48-hour window, and read gateway lines for Telegram, Discord, and Slack. When Discord said it had no project, the log showed a reply had been sent, and the classifier showed why the memory was missing. I compared that behavior with Assignment3_local_Gemma.pdf Part 4 and with section 4.4 of the assignment description before treating the window as complete.

## 5. What you learned

The assistant could draft a router that looked right and still drop shared memory, because a short question was classified as simple and the local call received only that sentence. It also could not see that Discord had answered inside a thread, or that Windows OpenSSH failed because the Cloud SDK path contained a space. I had to read the gateway log, the classifier, and the Hermes memory path myself before the three chats actually shared one fact.
